Your task is to classify a given programming-related question (similar to those found on Stack Overflow) as either "Low Complexity" or "High Complexity" based on the criteria provided below. Your rating should be consistent across similar types of questions.

Complexity Rating System:
1. Low Complexity Question:
A question is considered "Low Complexity" if it meets one or more of the following criteria:

Direct Answer: Can be answered with a single, straightforward code snippet or a concise explanation of a basic concept.

Basic Syntax/API Usage: Involves fundamental language syntax, common library functions, or well-documented API calls without intricate interactions.

Typo/Minor Error: The problem is likely due to a simple typo, a missing import, or a very common, easily identifiable error.

Common Knowledge: Relates to widely known programming patterns, data structures, or algorithms that are part of a standard curriculum or common practice.

Single Concept: Focuses on a single, isolated programming concept.

Examples of Low Complexity Questions:

"How do I reverse a string in Python?"

"What is the difference between let and const in JavaScript?"

"Why am I getting a NameError for my_variable in my Python script?"

"How do I add an item to a list in C#?"

"What is the basic syntax for a for loop in Java?"

2. High Complexity Question:
A question is considered "High Complexity" if it meets one or more of the following criteria:

Multiple Interacting Concepts: Requires understanding and combining several distinct programming concepts, libraries, or technologies.

Architectural/Design Focus: Involves discussions about system design, scalability, performance optimization, best practices for large applications, or choosing between different architectural patterns.

Debugging Complex Systems: Requires deep analysis of a non-obvious bug within a larger system, involving multiple components, asynchronous operations, or subtle interactions.

Algorithm Design/Optimization: Asks for the design or optimization of a non-trivial algorithm, especially those involving graph theory, dynamic programming, or advanced data structures.

Performance/Concurrency Issues: Deals with race conditions, deadlocks, memory leaks, or optimizing code for specific performance bottlenecks.

Ambiguous/Open-ended: The problem statement is broad, requires significant clarification, or has multiple valid solutions depending on context.

Integration Challenges: Involves integrating disparate systems, APIs, or technologies that are not designed to work seamlessly together.

Examples of High Complexity Questions:

"How can I optimize a real-time data processing pipeline using Apache Kafka and Spark Streaming to handle millions of events per second while ensuring fault tolerance and exactly-once processing?"

"What are the best practices for implementing a microservices architecture with service discovery, API gateway, and distributed tracing in a cloud-native environment?"

"I'm experiencing a memory leak in my Node.js application when processing large file uploads concurrently. How can I diagnose and fix this, considering potential event loop blockages and garbage collection issues?"

"Design an efficient algorithm to find the shortest path in a dynamic, weighted graph where edge weights can change over time, and the graph can have millions of nodes."

"How do I implement a custom authentication and authorization system in a Spring Boot application that integrates with an external OAuth2 provider and supports role-based access control for different user types?"

Determine which category the question predominantly falls into.
